# Cloud ingress migration

Approved scope: move the existing single Traefik instance and complete ACME state from win-hhx to vm-12-8-ubuntu, retaining old storage and rollback. Never disconnect Windows without separate approval. No database, Vercel, application image, credentials or unrelated services change.

## Source and deployment

This public repository contains configuration only. ACME state, private keys, tokens, kubeconfigs, real contact email and sensitive backups must never enter Git, logs or chat. No automatic deployment workflow is enabled. Existing Make targets are manual and use the `ser` SSH alias; this migration uses the already-verified `server` alias with strict host-key checks. Do not run broad rsync or synchronize examples as live objects.

Review the exact commit and changes, archive that full commit, and independently verify the archive SHA256 on the server. Render the contact placeholder on the server from the existing approved HelmChartConfig without printing it. Atomically install ONLY the rendered `src/k3s/traefik-config.yaml` as `/var/lib/rancher/k3s/server/manifests/traefik-config.yaml`; never modify generated `traefik.yaml`. Keep fixed source receipt and root-only baseline outside Git. Apply PVC and Node label separately, in the sequence below. Do not follow moving branch heads.

## Sequence

1. Back up old manifest, HelmChartConfig, Deployment, PVC/PV and affected Node label state under a root-owned 0700 directory. Record public certificate fingerprints and successful HTTP content hashes. Set the OLD PV reclaim policy to Retain. Keep its PVC and contents intact.
2. Create `traefik-cloud` and a temporary cloud-pinned consumer with the exact custom taint toleration. local-path uses WaitForFirstConsumer. Verify new PV affinity is vm-12-8-ubuntu and protect it with Retain. Prepare images before outage.
3. Wait for Helm reconciliation to finish, then scale the existing Deployment to zero directly and wait for all old Traefik processes to exit. Installed chart 40.1.3 uses `default 1` for deployment.replicas, so Helm values replicas=0 renders one replica and is NOT a valid stop mechanism. Keep the existing manifest unchanged during transfer; verify replicas remain zero before reading/writing state. During this maintenance window HTTPS is interrupted. Do not run two ACME writers.
4. A temporary Windows-pinned helper mounts only the original PVC read-only. Stream its complete acme.json through Kubernetes exec and two existing strict SSH sessions connected by an anonymous pipe: Windows volume -> Kubernetes encrypted exec -> cloud SSH -> WSL memory pipe -> cloud SSH -> destination volume. Neither WSL disk nor generic temporary files receive key material. Helpers have no service-account token and minimal resources. The cloud receiver validates JSON structure, limits input size, atomically writes inside the restricted volume, sets 0600 and UID/GID 65532, and reports hashes/metadata only. Do not print key material or exception data. Compare source and destination SHA256.
5. The chart mounts with fsGroup, which can change acme.json from 0600 to 0660. A non-root owner initContainer must restore 0600 after every mount and before Traefik starts; it fails if the migrated file is absent, rather than creating an empty account. Delete helpers after successful transfer. Install reviewed cloud-pinned HelmChartConfig with existingClaim=traefik-cloud, single replica, Recreate and unchanged resolver. The Service annotation `svccontroller.k3s.cattle.io/tolerations` must include the custom cloud taint before enabling the ServiceLB allowlist; Traefik Pod tolerations do not apply to ServiceLB. Add cloud enablelb=true after cloud ingress and the generated ServiceLB tolerations are ready. This switches ServiceLB into an allowlist for ALL current/future LoadBalancer Services; currently only Traefik uses it. Windows stays unlabeled.
6. Verify PV and Pod placement, EndpointSlices, cloud ServiceLB, DNS dependencies, public trust/SAN/expiry/fingerprint, home/static/health endpoints and memory headroom. Test explicit cloud-IP Host/SNI routing from outside the server. This proves the current route, NOT actual Windows-offline resilience or a future ACME renewal.

## Rollback

Wait for Helm to be idle, scale cloud Traefik Deployment to zero directly and confirm no writer remains before restoring the manifest. Restore old manifest/resolver/PVC reference and Windows placement; old PV remains Retain. Restore only the ServiceLB label added by this change if it was absent before. Keep both PVCs and new data; never delete either to roll back. Start exactly one old instance and verify HTTPS. If cloud ACME state has changed (for example renewal), reconcile the latest state before returning to the old copy. Restoring a manifest file alone does not delete Kubernetes objects; wait for actual Helm reconciliation. Old volumes/backups require a separate future retirement decision.

## Scheduling and capacity

Application repositories own frontend/backend Deployments: use examples/cloud-web-podspec.yaml. Compute Jobs/CronJobs explicitly choose win-hhx: see example. These are scheduler constraints, not admission enforcement. No extra admission controller or policy is installed. CoreDNS/provisioner/metrics currently run on cloud but their templates are not yet pinned; persistent system-component scheduling is separate follow-up. Leave 600-800Mi MemAvailable safety margin; Traefik currently uses roughly 110Mi, plan 128-256Mi rather than assuming zero overhead.
